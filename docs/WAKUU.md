## 模型与判分

底模：[IDEA-CCNL/Erlangshen-Roberta-110M-NLI](https://huggingface.co/IDEA-CCNL/Erlangshen-Roberta-110M-NLI)，固定 revision `864d25be3ce5e90d9193cb49d9fbd52722cdc6b0`。
发布方声明 Apache-2.0，安装包保留许可及修改说明。
瓦库比较“玩家的小问答案”与“这一小问的参考结论”，输出矛盾、信息不足、语义支持三个概率。
它不生成答案，也不能调用游戏命令。金币和物品只能由固定评分细则发放。

- 数值小问使用确定性规则，接受规定单位的换算，拒绝同时列多个互斥答案。
- 概念小问的语义支持概率至少 0.85、矛盾概率低于 0.1，才给该评分点分数。
- 明显矛盾或缺少评分点时记 0 分；模糊区间显示待复核，暂不计该评分点，也不自动将整题纳入错题。
- 每个评分点满分或 0 分，练习分合计 100；当前不是自由作文连续打分，也不是原卷整题评分。
- 答案与参考结论合计最多 192 tokens。过长会明确要求精简，不静默截断。
- 模型缺失、校验失败或推理异常可以重试，不按错误提交记录。

模型仅在第一次评分时加载，随后复用 CPU 会话，最多使用 4 个推理线程。
游戏 Mod 加载器不会自动处理 NuGet 依赖，因此显式注册 ONNX 托管与原生 DLL；版本采用 1.27.1，与本机 DrawAndGuess 一致。

## 本次微调与实测范围

训练数据为项目编写、显式标注的 240 对中文计算机概念，不含玩家答案或未核实授权的教材段落。
冻结大部分底模，只训练最后两个 Transformer 层、pooler 和分类头，5 轮、学习率 2e-5、随机种子 408。
另有 20 对未用于梯度训练的开发验证样例，其中 7 对语义支持；这是调参和选择精度使用的开发集，不是独立考试测试集。

| 比较 | 三分类正确 | 达到给分阈值的正确样例 | 错误样例被给分 |
| --- | ---: | ---: | ---: |
| 底模 FP32 | 13/20 | 1/7 | 0 |
| 微调 FP32 | 17/20 | 4/7 | 0 |
| 微调 FP16 | 17/20 | 4/7 | 0 |
| 微调 INT8（逐条推理） | 16/20 | 见比较明细 | 1 |

INT8 虽较小、较快，但产生错误给分，未发布。所选 FP16 保持了这组开发样例上的 FP32 结果。
本机 FP16 CPU 跑完 20 条约 0.5–1.2 秒，不包含首次加载；运行时和机器不同会有波动。
17/20 不能解释成大题批改准确率；正确同义表达仍可能得分不足。尚不支持可靠的任意算法、伪代码、长证明或开放问答批改。
八道练习的参考答案满分验证只检查接入正确，不证明泛化能力。

训练明细：`reports/wakuu-training.json`；精度比较：`reports/wakuu-precision.json`。
所选模型 SHA-256：`a2742d55f4d2b20c153452184392cea1b50ef26dd8a5660042efa14ce102d0b8`。

## 本地重建

开发机需要 Python、PyTorch、Transformers、NumPy；本次使用 torch 2.5.1+cu121、transformers 4.46.2。
GPU 可选，CUDA 不可用时训练脚本回退 CPU。游戏运行不依赖这些开发库。

```powershell
./PrepareWakuu.ps1
dotnet run --project tests/CoreTests.csproj
./Build.ps1 -SkipAssets -Install
```

脚本下载固定底模并校验权重 SHA，构建题目与样例，将 ONNX 开发库装入 `.tools/ai-python`，训练并比较候选精度。
训练候选写入 `.tools/ai/train`；验证通过才更新 `models/wakuu`，失败不将候选覆盖正式模型。
首次准备需要联网下载底模，之后游戏始终只读本地文件。
固定底模、种子和配置用于追溯，但不同 GPU/库版本不保证训练权重逐字节一致。

## 扩题与继续训练

原有 8 道自编题和训练样例在 `tools/ai/build_corpus.py`；196 道导入题经过 `tools/import_essays.py` 提取，`tools/build_essays.py` 合并并附加经过参数核对的计算评分点。
完整题库为 `game/Spire408/Data/essays.json`，来源与当前判分覆盖见 `ESSAY-IMPORT.md`。
新增自动评分点仍需要核对来源、单位、结论，不能仅将整段参考答案丢给模型。

后续应优先补充真实同义表达、遗漏条件、否定结论、混合正误答案，再用独立人工标注集评估漏给分与误给分。
每次更改评分细则必须更新题目 revision；训练样例与验证样例分开维护，模型版本记录在 `model_version`。
避免在模型元数据中使用 `version` 字段，游戏会将含该字段的 JSON 误认为 Mod 清单。
不要把拒绝候选、PyTorch 检查点或开发依赖加入分发包。
