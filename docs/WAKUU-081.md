# 0.8.1 判分优化与80%目标

日期：2026-10-27。本轮正式模型仍是dev2，权重没有更换；评分流程标识为`wakuu-nli-408-dev2/passages-081`。

## 修复了什么

0.8.0在“答案+参考评分点”较短时，会把整段答案直接交给NLI。即使这段文字包含多个小问，模型也需同时处理不相关的结论，造成大量漏给分。

0.8.1对较短的多句答案也先做评分点检索，与较长答案使用相同的逐句核对路径。置信阈值仍为0.85，矛盾概率上限仍为0.1；没有通过放宽阈值获得更漂亮的指标。数字规则、过程复核和游戏奖励分档保持不变。已经记录的历史分数不重算。

124道新增语义题使用参考文本进行接入检查时，平均练习分从76.45升到97.94，最低从16升到59。这里的分数只是“参考文本能否被本流程正确接收”，不是实际作答准确率。

## 新评测集与80%的含义

本轮项目编写48个知识点家族，每科12个：每科前4个用于补充训练，第5、6个用于开发验证，最后6个保留测试。每个家族有两种正确表达、一种错误结论、一种相关但未回答评分点的表达。

新测试集共24个家族、96条样例：48条正确、24条错误、24条不完整。它们不参与本轮补充训练或检查点选择。原模型预训练及早期题库训练可能已涉及相同知识，因此不能称为知识本身从未见过；本集合也不是独立人工标注的真实答卷。

指标以最终是否给分计算：正确表达不给分也算判错，不能把待复核样例从分母中排除。

| 指标 | 0.8.0流程 | 0.8.1流程 |
| --- | ---: | ---: |
| 总体给分决策正确 | 78/96（81.25%） | 78/96（81.25%） |
| 正确表达获得给分 | 31/48（64.58%） | 31/48（64.58%） |
| 错误/不完整表达被误给分 | 1/48（2.08%） | 1/48（2.08%） |

这组新样例没有显示总体判断率提升。本次明确改善的是混合多个小问的参考文本漏分，不能把它说成从某个低准确率提高到了81.25%。总体80%的小样本目标与“正确答案80%能得分”是两个不同要求，后者目前尚未达到。

样例源码为`tools/ai/marking_families_081.py`；基准程序为`benchmarks/MarkingBench.csproj`。原始结果保留在本机`reports/wakuu-heldout-081-baseline.json`和`reports/wakuu-heldout-081-improved.json`；公开汇总及逐例判分结果见 [evaluations/wakuu-081.json](evaluations/wakuu-081.json)。

## 补充训练候选为何未部署

尝试从dev2检查点继续微调最后两个Transformer层、pooler和分类头：4,224条包含重放数据的训练对、52条开发验证，3轮，学习率1e-5、随机种子408081。测试家族未进入梯度训练或选择过程。

候选的开发验证分类结果有所改善，但在已有68条诊断回归中新增了错误给分；新开发集的最终给分决策也没有优于现有权重。因此候选仅保存在`.tools/ai/refinement-train-081`，没有替换`models/wakuu`。本轮没有用保留测试集挑选权重或调整置信阈值。

正式权重仍为204,768,513字节，SHA-256为`cd1a655635fec6f9bb33e5b95271212fc550c816489271939ea422bdc73356c3`；完整Mod仍低于500MB，游戏推理完全离线。

## 重现与下一步

```powershell
python -X utf8 tools/ai/marking_families_081.py
dotnet run --project benchmarks/MarkingBench.csproj -- . .tools/ai/marking-081/dev.json models/wakuu reports/wakuu-dev-081.json
dotnet run --project benchmarks/MarkingBench.csproj -- . .tools/ai/marking-081/test.json models/wakuu reports/wakuu-test-081.json
dotnet run --project benchmarks/MarkingBench.csproj -- . canonical models/wakuu reports/wakuu-reference-081.json
```

需要本地准备的模型；reference模式另外需要导入的大题库。新项目编写的事实样例公开，来源题库派生的训练缓存和模型权重仍不随源码仓库发布。

后续应优先提高正确表达给分率，增加按评分点核实的不同正确解法、同义改写和条件遗漏样例，再建立新的独立留出集。任意代码执行正确性、复杂证明和绘图过程仍不由这个小型NLI模型验证。124道语义题继续标注实验性。
